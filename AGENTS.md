# Project Instructions

## Required References

Before planning, implementing, reviewing, testing, or documenting this portfolio project, read these files in order:

1. `docs/PORTFOLIO_IMPLEMENTATION_SPEC.md`
2. `docs/LEARNING_GUIDE_KO.md`
3. `docs/STEP_BY_STEP_KO.md`

`docs/PORTFOLIO_IMPLEMENTATION_SPEC.md` is the authoritative implementation contract. The two Korean documents are learner-facing guides and must remain consistent with the implementation contract and the application code.

## Project Rules

- Use semantic HTML, mobile-first CSS, and browser-native JavaScript.
- Do not add React, Vue, Angular, jQuery, Bootstrap, Tailwind CSS, or another application or CSS framework.
- Keep the user event -> state change -> DOM render flow explicit in interactive features.
- Use the placeholders defined in the documentation until the user provides real profile information.
- Keep implementation changes small, explainable to a beginner, and aligned with the learning goals.
- When behavior, selectors, state names, thresholds, commands, or deployment steps change, update every affected guide in the same task.

## Verification

Before reporting completion, verify the relevant requirements and checklists in the implementation specification. For application changes, run targeted syntax and behavior checks and confirm that documentation examples still match the implemented selectors and state contracts.
